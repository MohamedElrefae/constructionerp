STEP 6 - ROOT CAUSE OF THE FIRST RUN'S TypeError  (determined by probe)
------------------------------------------------------------------------------
  The failing line was:
      L("  rows affected : %s" % affected)

  PROBE RESULT (throwaway table, no real data touched):
      frappe.db.sql("DELETE ...") -> type tuple, value ()   <-- EMPTY TUPLE
      "x : %s" % ()  ->  TypeError: not enough arguments for format string

  EXPLANATION: in Python, "%" with a tuple on the right-hand side treats that
  tuple as the ARGUMENT LIST, not as a single value. An empty tuple supplies
  ZERO arguments while the format string requires ONE, hence the error.
  (SELECT statements return int/tuple-of-row, which is why COUNT worked.)

  IMPACT ON THE OPERATION: NONE. The line sat AFTER frappe.db.commit(), so
  the DELETE was already durable. The rollback() in the except block was a
  no-op because the transaction had committed.

  CORRECTION APPLIED: this log formats with str() and concatenation instead
  of "%" so no format-string hazard remains.

  SECOND LEARNING: frappe.db.sql("DROP TABLE ...") raises ImplicitCommitError
  in this Frappe build; DDL must be executed outside the ORM (mysql CLI).
