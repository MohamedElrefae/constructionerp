## 1. Purpose & Strategic Scope

Prior to this work item, fourteen masters were made active across financial, operational,
classification, and organizational domains. However, two load-bearing gaps remained:
1. **The Print Verification Gap**: The Governance ADR (`BILINGUAL_GOVERNANCE_PRINT_IMPORT_PERMISSION.md`)
   certified Print as *Documented as Unverified* due to the absence of automated bilingual print fixtures.
2. **The BOQ Mixed-Convention Gap**: Within the Construction domain, `BOQ Structure` carried `description_ar`
   but lacked `title_ar`, forcing legacy tests and exports to smuggle Arabic text directly into the
   English `title` field. Furthermore, the `enable_bilingual_boq_print` rollout flag existed in `Construction Settings`
   but was completely disconnected in `boq_export_service.py`.

This work item enables bilingual capabilities on `BOQ Structure` and `BOQ Header`, establishes the
immutable WBS code exclusivity invariant, connects and tests `enable_bilingual_boq_print`, and fixes
the legacy test workaround in `test_boq_excel_parser.py`.

## 3. The WBS Code Exclusivity Invariant

`wbs_code` on `BOQ Structure` is algorithmically generated by `generate_wbs_code()` based on tree
position (`01`, `01.001`, `VO-002-01`) and is referenced across contracts, Variation Orders, Material
Requests, and Excel sheets (`source_wbs_code`).

**Invariant Contract:**
- `wbs_code` is **completely excluded from the bilingual surface**.
- No `wbs_code_ar` or `wbs_code_ar_norm` field will ever be introduced.
- In `bilingual_registry.json`, `BOQ Structure` declares `code_field: "wbs_code"`.
- Automated tests will explicitly assert that `wbs_code` remains language-neutral ASCII alphanumeric and never accepts Arabic script, bidi marks, or normalization translations.

## 4. Print Architecture & Flag-Gated Policy

### A. Strict Flag-Gating Policy
- Rollout flag: `enable_bilingual_boq_print` in `tabConstruction Settings` via `construction.services.feature_flags.is_enabled`.
- **Default State (Flag OFF / `0`)**: Existing print and PDF export behavior is **100% byte-identical**. Monolingual exports remain completely unregressed.
- **Active State (Flag ON / `1`)**: Enables true bilingual dual-language rendering:
  - Header title: renders `header.title` and `header.title_ar`.
  - Linked project: renders `header.project_name` and `header.project_name_ar` (pulled from active `Project` master).
  - Tree section / item titles: render `node.title` and `node.title_ar`.
  - WBS codes: remain strictly language-neutral ASCII.

### B. Service Diff Boundary
- The **Zero-Service-Edit Invariant** on `bilingual_service.py` and `search.py` is **strictly maintained (0 diff lines)**.
- Print export logic lives in `construction/services/boq_export_service.py` and Jinja templates (`boq_print_format.html`, `boq_header_print.html`). Wiring the flag here is an authorized print-feature enablement, distinct from the core bilingual engine.
