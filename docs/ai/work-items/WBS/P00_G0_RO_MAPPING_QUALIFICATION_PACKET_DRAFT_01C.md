## Gate and cleanup model — proposed only

Authorization and target binding precede any operation. Logical gate states are `NOT_STARTED`, `PRECHECKED`, `TX_OPEN`, `VERIFYING`, `VERIFIED`, `QUERY_ALLOWED`, and `STOPPED`; separately tracked cleanup states are `NOT_STARTED`, `IN_PROGRESS`, `CONFIRMED`, `UNKNOWN`. In the same attempt:

1. `NOT_STARTED -> PRECHECKED` only after an independently qualified witness, exact approved method and statement IDs, resource binding, logging and authorization are confirmed. No observer is currently qualified.
2. `PRECHECKED -> TX_OPEN` only after a checked connection/transaction pre-state and approved read-only start. `TX_OPEN -> VERIFYING` allows **only separately reviewed non-mutating verifier IDs**, never identity IDs. No such catalog is approved.
3. `VERIFYING -> VERIFIED` requires independently evidenced active enforcement, current same-transaction correlation, visibility and all approved proof prerequisites. Metadata or a successful query alone is insufficient. `VERIFIED -> QUERY_ALLOWED` permits only the fixed identity IDs on the same unbroken verified transaction, while proof remains valid.
4. Any unexpected operation, changed identity, connection, transaction, missing proof, timing ambiguity, unqualified witness or failure transitions gate to `STOPPED` permanently for that attempt. No identity query may be sent from `STOPPED`. A fresh attempt, if later justified, requires fresh scope-specific authorization; no broader privileges.
5. After success or stop, begin cleanup separately: safe rollback and close on the same trustworthy connection; `CONFIRMED` only on independently defined positive evidence, otherwise `UNKNOWN`. Do not delete a resource of uncertain identity; quarantine pending separately authorized remediation. Stop does not prohibit cleanup, but cleanup never reopens the gate. Any incomplete cleanup makes the attempt INCOMPLETE. Cleanup and evidence sealing order must be designed and independently qualified; no present supervisor self-report suffices.

Expiration and freshness must be pinned in a later independently reviewed method and supported by a trusted clock. Until then proof is UNKNOWN, never presumed fresh. No operational state machine, verifier IDs or witness implementation is claimed here.
