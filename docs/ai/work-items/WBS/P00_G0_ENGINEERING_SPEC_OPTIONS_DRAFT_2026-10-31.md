## 1. Non-mutating active READ ONLY verifier and transaction correlation

**Technical design candidate — BLOCKED.** A dedicated non-reconnecting connection with a pinned client/driver, approved principal, no dynamic SQL/multi-statement execution, and an exact reviewed statement-ID allowlist would establish `START TRANSACTION READ ONLY`. A gate rejects identity statement IDs before the active-transaction proof is independently verified. A server-generated connection identifier is held in memory for correlation and never output; it is not sufficient alone because of reuse, reconnect and same-session transaction changes. The candidate under study is a fixed column-projected `INFORMATION_SCHEMA.INNODB_TRX` check correlating its thread field and `TRX_IS_READ_ONLY` with this live connection. Exact schema, row existence, visibility, freshness, privileges, connection/transaction lifetime, engine coverage and the relationship between that state and enforced access mode are unknown. No query, privilege or principal is approved by this draft. Do not collect query text, unrelated sessions or account names, or assume a metadata row/default variable proves enforcement. If the observation needs broader visibility or PROCESS, stop; no privileged retry.

A viable target method must independently establish, without a mutation attempt, that database-enforced READ ONLY is active **for the same transaction** before identity statements. Continuity proof must invalidate the gate on reconnect, implicit commit, connection reuse, unexpected statement, server/driver change, lost witness or uncertain transaction state. There is presently **no qualified non-mutating proof**: the candidate metadata check is a hypothesis, not an oracle. Do not issue database identity queries on that basis. A qualified boundary witness must independently establish pre-gate denial and same-transaction ordering without capturing SQL or personal identity; silence without demonstrated full channel coverage is UNKNOWN. No witness is qualified.

**Failure/close design.** Any mismatch, missing/duplicate/stale row, unknown privilege/visibility, log leakage risk, changed connection, unexpected schema, timeout or uncertainty stops the attempt. No automatic retry with broader privilege. On the same trustworthy connection, attempt the approved rollback and close, then close local handles. Rollback/close failure, disconnect or uncertainty => INCOMPLETE; never claim success. Define close evidence before a future grant; do not infer closure from a rollback statement alone. No raw exception text or query bodies enter output.

**Redacted output candidate.** Fixed-schema fields: approved opaque attempt/grant and method version, approved bounded UTC interval, baseline version, stage enum, `MATCH/MISMATCH/UNKNOWN/NOT_RUN` for preapproved fields, overall `COMPLETE/INCOMPLETE`, cleanup `CONFIRMED/UNKNOWN`, and preapproved limitation codes. No free text, raw values, connection ID, user name, document ID, SQL or exception. Even an enum is suppressed/coarsened if it identifies an unexpected value or sensitive column; if no safe output or independent attestation exists, emit nothing and mark reliance/campaign INCOMPLETE through a separately approved safe channel. The exact wire schema, identifier scheme, channels and destination are not approved or qualified.

**Required evidence.** Independent source/design review; exact version/build and engine semantics; privileges and complete visibility proof without prohibited data; boundary witness coverage, reconnect/ID-reuse/implicit-commit and pre-gate negative controls; independently observed active enforcement and close behavior, without target mutation; logging, redaction and runtime-drift evidence. A separately authorized isolated synthetic lab may use controlled mutation negative/positive cases only on synthetic fixtures, but lab success alone cannot establish target enforcement or justify a target write. If no non-mutating target proof can be qualified, target identity check remains blocked; this is not a decision to weaken the requirement.

**Limitations / decisions.** The observed database state is not runtime application-code binding or uninterrupted writer exclusion. Exact principal and safe authentication are unapproved and unqualified. Owner later authorizes any named target/principal and each assessment or qualification separately; engineering must design methods, not ask the owner to invent them.
