## Property and gate

For the one named principal's specifically identified server connection and its single uninterrupted transaction, a qualified, non-mutating witness must demonstrate that database-enforced READ ONLY is active before any preapproved identity query is transmitted, and remains applicable through those queries. The precise operation and statement/engine coverage must be enumerated and reviewed for the eventual query set; SQL access mode must not be conflated with a global read-only option or an InnoDB optimization flag. The witness must cover required SQL-layer enforcement, not assert that all conceivable operations or engines are covered. Temporary-table DML is a specific exception/complexity to be evaluated, not silently treated as forbidden by the transaction mode. No production write attempt, including one expected to be rejected, is permitted or can be used as target qualification evidence. A non-mutating witness might be possible; no such method or trust chain is established here. Target proof is unavailable with presently identified methods, not shown impossible.

Threats to address include accidental or hostile transaction replacement, wrong or multiplexed session, replay, stale or incomplete metadata, overprivileged/compromised verifier, altered server/proxy, side effects and evidence leakage. A qualified method must state which actors it can and cannot withstand, its server/instance and topology assumptions, and its trusted computing base. It must detect unauthorized session or state changes or stop. Cluster/failover, proxy, autocommit, implicit commits and connection pooling require explicit treatment.

Gate passes only if a separately accepted method and independent attestations establish exact-build/runtime binding, active enforcement, same-transaction continuity from pre-gate to the identity queries, complete permitted visibility, no forbidden side effects, pre-gate non-transmission, redacted evidence and verified cleanup. Evidence must include reviewed source/patch provenance, method-specific visibility and correlation analysis, independently witnessed positive/negative controls in a separately authorized disposable environment, and later instance-specific non-mutating evidence; lab outcomes alone cannot prove target enforcement. No concrete method meets these criteria. A missing or uncertain item is UNKNOWN/INCOMPLETE and denies the gate; separately record confirmed failures if safe. Future acceptance remains subject to the owner's existing governance, including custody restrictions; no acceptance or authority is granted here.

## Public source trace and package provenance

- The public upstream [transaction code](https://github.com/MariaDB/server/blob/mariadb-10.11.14/sql/transaction.cc#L146-L196) sets thread read-only state for an explicit READ ONLY transaction. The [InnoDB helper](https://github.com/MariaDB/server/blob/mariadb-10.11.14/storage/innobase/handler/ha_innodb.cc#L1581-L1589) consults that state. [Transaction startup](https://github.com/MariaDB/server/blob/mariadb-10.11.14/storage/innobase/trx/trx0trx.cc#L849-L860) assigns `trx->read_only` from multiple conditions, including server read-only and the SQL thread flag; it also assigns true for a qualifying autocommit case. Thus the InnoDB flag is not shown to be equivalent to an explicit SQL READ ONLY declaration. This partial static trace does not establish all paths, enforcement, build binding, or runtime behavior.
- [Cache fill](https://github.com/MariaDB/server/blob/mariadb-10.11.14/storage/innobase/trx/trx0i_s.cc#L435-L457) copies the InnoDB flag into a cached row; [schema output](https://github.com/MariaDB/server/blob/mariadb-10.11.14/storage/innobase/handler/i_s.cc#L459-L465) emits it. The [common reader](https://github.com/MariaDB/server/blob/mariadb-10.11.14/storage/innobase/handler/i_s.cc#L159-L184) checks global PROCESS and invokes a possibly refreshed cache. [Cache code](https://github.com/MariaDB/server/blob/mariadb-10.11.14/storage/innobase/trx/trx0i_s.cc#L905-L915) uses time since last read as a refresh condition, and [cache population](https://github.com/MariaDB/server/blob/mariadb-10.11.14/storage/innobase/trx/trx0i_s.cc#L978-L1020) skips not-started transactions. Treat shared-cache lifecycle, row truncation, warning delivery and cross-session effects as unresolved until fully traced. Reading may refresh a cache and affect warnings or logs; it is not automatically side-effect-free.
- Public Ubuntu archive [source descriptor](https://archive.ubuntu.com/ubuntu/pool/universe/m/mariadb/mariadb_10.11.14-0ubuntu0.24.04.1.dsc) and [Debian packaging archive](https://archive.ubuntu.com/ubuntu/pool/universe/m/mariadb/mariadb_10.11.14-0ubuntu0.24.04.1.debian.tar.xz) were downloaded into process memory and hashed; no package was installed or executed. Descriptor SHA-256 `f2812de13770d1bc5146e8fd4657b899fe0ae9e3dbc04171f96fb3bbdd12f837`; packaging archive SHA-256 `c6086b72136834b2247fb9a837e03ee2fbfa49615bb0422973d7f8f2384d1bd7`, matching the digest printed in that descriptor. The archive's `debian/patches/series` lists `env-perl-usr-bin-perl.patch`, `mroonga-mrn-lib-dirs-path-reproducible-build.patch`, `install-files-into-usr.patch`, and `MDEV-37411-suppress-new-warning-about-native-aio.patch`. ## Correlation, data access and witness requirements

A timestamp, thread ID, transaction ID, snapshots or metadata indicators, individually or in combination, are insufficient without a qualified binding method. The reference PROCESS check is global, potentially exposing more than the bounded operation needs. No PROCESS grant or administrative inspection is authorized. An independent witness requires an authenticated trust root and verified build and instance binding, live same-transaction correlation, replay and substitution resistance, separation from the subject and evidence author, scoped disclosure, independent visibility and control evidence, and a defined threat model.
