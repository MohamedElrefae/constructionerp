## 1. Outcome precedence and adverse findings

An attempt is a separately authorized, bound execution of one variant in one disposable generation. Each attempt has one result: PASS, FAIL, UNKNOWN or NOT_RUN. A verified expected denial can be PASS only with a preapproved exact oracle, independent positive controls, correct binding, safe output and confirmed cleanup; an incidental stop or unqualified witness is UNKNOWN. NOT_RUN includes authorized but not started. A proven contrary observation is an adverse finding, preserved independently from the aggregate classification; it is never silently erased by later PASS or redaction. If adverse evidence is contradictory or untrusted, record UNKNOWN through a separately qualified non-leaking channel; do not fabricate evidence or disclose prohibited data.

Proposed ordering: an empty or unapproved catalog means campaign INCOMPLETE. For each required variant retain all attempts; no attempts or all NOT_RUN => NOT_RUN; unresolved, missing, invalidated, contradictory or untrusted evidence => UNKNOWN; otherwise a confirmed uncorrected FAIL => FAIL; otherwise at least one PASS and no FAIL => PASS. A later PASS does not clear an earlier confirmed FAIL. Case aggregation: all required variants NOT_RUN => NOT_RUN; any missing/UNKNOWN/NOT_RUN mixed with executed results => UNKNOWN; otherwise any FAIL => FAIL; otherwise all PASS => PASS. When an adverse finding exists alongside unknown evidence, case classification is UNKNOWN and the adverse finding is separately reported; UNKNOWN does not convert the adverse finding into a pass. Campaign: any UNKNOWN/NOT_RUN or unqualified required binding, independent attestation, cleanup or seal => INCOMPLETE; otherwise any case FAIL => FAILED; only all cases PASS plus independent reconciliation and acceptance of applicable evidence => LAB_CASES_COMPLETE. This is a bounded lab classification, not target qualification, G0 closure, activation or a waiver.

## 2. Invalidation and authority

Observed pre-gate transmission, canary escape, lost witness or other suspect evidence immediately stops the attempt and suspends reliance on affected findings and dependent conclusions. This immediate safety suspension is provisional, not a self-issued final attestation. A separately authenticated, independently adjudicated append-only invalidation or correction disposition must follow; if authority, safe channel or evidence is unavailable, affected results remain UNKNOWN and campaign INCOMPLETE. Final disposition must bind campaign, catalog, generation, attempt and affected records through reviewed non-sensitive anti-replay references; original records and adverse findings are retained without prohibited values. A later PASS cannot clear a confirmed failure without an independently adjudicated correction. Invalidation discovered after a campaign result suspends that result and cascades to dependent conclusions; reopening and any further attempts require a fresh scoped authorization. Trust root, authority, role boundaries, binding and correction criteria remain unqualified. Incident investigation and any changes to handling requirements need separate authorization; this draft permits no raw-evidence exception.

An oracle must be outside the candidate's control boundary and demonstrably not derived solely from the candidate's verdict; selection, role, source, integrity and conflict-of-interest criteria require independent review and qualification. An incidental error, blanket denial, missing control, loss of coverage or unknown observer integrity is UNKNOWN. R02 is a synthetic-lab-only READ WRITE mode control with no write in that variant; it passes only if an independent lab oracle establishes that the checker refused the write-capable mode, not merely that a query failed. The synthetic boundary witness must cover all transmission channels for the entire pre-gate window, distinguish statement-ID attempts without collecting SQL or user identity, and have independent positive controls proving it can detect a synthetic transmission plus negative controls for spurious events. Observed forbidden transmission stops the attempt and triggers provisional suspension under section 2. Silence without demonstrated full coverage is UNKNOWN, never proof. ## 4. Version grammar and redacted outputs

The only MATCH_REFERENCE is the exact ASCII byte sequence `10.11.14-MariaDB-0ubuntu0.24.04.1`, with no normalization. Proposed ordered classification: (1) non-ASCII, control characters, leading/trailing whitespace or input not matching the grammar below => UNKNOWN; (2) parse core; if numeric triple differs from `10.11.14`, => NUMERIC_MISMATCH and stop; (3) exact full reference => MATCH_REFERENCE; (4) otherwise => UNKNOWN and stop. The grammar is three unsigned decimal components separated by dots, followed by either end-of-input or a hyphen and a nonempty ASCII suffix of letters, digits, dots or hyphens. Thus suffix numeric components are not core components; `10.11.14.5` is malformed/UNKNOWN, bare `10.11.14` is UNKNOWN, and the accepted full reference matches. Leading zero rules and size bounds are not yet qualified; if ambiguous => UNKNOWN. Record only preapproved classification, never raw non-match, its length or hash; suppress even classification if it indirectly identifies a suppressed value. Grammar and independent vectors are design proposals, not qualified implementation or target observations.
