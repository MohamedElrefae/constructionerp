**Design only. Not an executable grant; not qualified.** Supplements `P00_G0_GRANT_SPECIFICATIONS_DRAFT_2026-10-31.md` and the two owner-provided handoffs. This document proposes procedures, output rules and qualification criteria. It does not assert actual UID, permissions, principal, visibility, active transaction mode, runtime binding, evidence location availability, or any target facts. The primary drafting work did not access the target, socket or custody path. A delegated reviewer reported an unauthorized site-path metadata inspection and inspection of site configuration key names; see incident note below. P00/G0 OPEN; H01/H02 OPEN/BLOCKED; P1 DEFERRED; P2 implementation, provisioning, native testing and deployment PAUSED. Accepted artifact bytes and hashes remain unchanged. ## 1. Grant envelope and common controls

Each subsequent operation needs a separate explicit current grant: unique ID and version; operator and permitted principal; exact resource, operation, purpose, time window, single attempt/repeat limits and expiry; prerequisites, approved procedure version and hash; independent reviewer; acceptance authority; revocation channel; permitted output and destination; failure/stop and escalation rules. Grant authorizes only listed operations. Stop on ambiguity, resource drift, revoked/expired grant, change of identity, method, driver, queries or environment, unqualified logging, or unexpected result. Never retry with broader privileges. Separate actions for assessment, creation/configuration, backup, recovery, qualification, access, collection, implementation and deployment need separate authorization. An approved destination is not evidence it is safe.

Operator must not emit raw session logs, credentials, raw unexpected values, SQL/script bodies, user identities, document identifiers or unrelated business records. Historical session has a reported credential exposure whose resolution is unknown. Avoid copying session logs. Error handlers must not serialize exception text, SQL, paths derived from unexpected inputs, connection strings or driver diagnostics. Disable client/driver debug and shell tracing; independently establish server/audit logging behavior before connection. If logging cannot be established safe without privileged inspection, stop and seek a separately scoped authorization; do not weaken the boundary.

## 2. Custody proposal and path algorithm

Owner-approved destination `/home/mohamed/p00-g0-evidence`, local owner `mohamed`, directory `0700`, files `0600`, umask `077`; retention until G0 closure or abandonment plus 12 months, deletion only by separate owner decision. Historic report of path absence is not a current guarantee. The numeric UID/GID are unknown: under a separate read-only administrative assessment grant, obtain local account mapping through a reviewed local mechanism, bind approved UID/GID to a signed/dated assessment, and verify effective UID equals the approved UID at execution; never infer the numeric value from the name. Require owner approval of any destination or custody policy change. No chown, parent chmod, ACL changes or privilege escalation in creation scope.

Proposed Linux design: single-threaded helper with umask 077, trusted initial root directory descriptor opened `O_DIRECTORY|O_NOFOLLOW|O_CLOEXEC`; walk each absolute path component one at a time via `openat` and `O_DIRECTORY|O_NOFOLLOW|O_CLOEXEC`, reject `.` and `..`, inspect `fstat` and ACLs on opened handles. Record device/inode, ownership, mode and ACL classification in a restricted assessment, not raw unrelated names. Trusted root/system ancestors must be owned by root and not writable by untrusted users; `/home/mohamed` must be owned by the approved UID, have no untrusted write access including ACLs, and have a verified directory identity. Mount, namespace, ACL interpretation, default ACL and privileged access risks require explicit qualification; if unknown stop. The home directory need not be assumed 0700 but must exclude untrusted modification of path components. Open handles and recheck identities immediately before creation; unsupported ACL or filesystem semantics stop. Local privileged users may bypass mode bits: this is a limitation, not organizational independence.

Under a separately authorized creation grant, using the verified parent descriptor and exact final component, `mkdirat(...,0700)` with no replacement; `EEXIST` or any other error stops, never adopt or delete an existing object. Open final component via `openat` with no-follow/directory flags; `fstat` and ACL check owner UID, mode 0700, directory type and identity; validate parent and final device/inode and permitted access; fsync directory and parent where supported. Any failure after mkdir leaves a potentially partial object, reports incomplete, and requires separately authorized identity-verified remediation; no automatic deletion. Race, parent substitution, unsupported sync, unexpected ACL or identity mismatch stops.

For later separately granted evidence writes: open files relative to held directory handle using `O_WRONLY|O_CREAT|O_EXCL|O_NOFOLLOW|O_CLOEXEC`, mode 0600 and umask 077; validate regular file, owner, mode, link count and ACL via descriptor. Write bounded canonical bytes, flush and fsync; hash the same bytes using SHA-256; close and fsync directory. Never overwrite. A manifest exclusively created after all package files includes package ID, version, UTC timestamps, names from a fixed safe allowlist, byte lengths, SHA-256 hashes, method and grant IDs, redaction schema, completeness and limitation classifications; avoid identifiers and unexpected values. Protect manifest hash separately. Any write, fsync, close, identity or hashing failure is incomplete; do not publish/accept a partial package. Exclusive file creation alone does not guarantee integrity against owner or privileged modification.

Permitted readers proposed: owner/custodian only, with no group/other or additional ACL access; any export to independent AI review must be an explicitly approved redacted copy, not direct filesystem access. Admin Construction holds authority and custodian roles per amendment, with disclosed reduced organizational separation. Custodian cannot self-accept custody evidence; independent AI review is not independent human custody. No independent human adjudicator exists; identify an acceptable non-self-acceptance process before custody acceptance, without inventing a separate human. Owner acceptance is recorded separately and amendment overrides older overlap-adjudicator language.

Backup proposal, subject to owner approval of destination and recovery policy and separate execution authorization: one owner-controlled encrypted removable storage device physically separate from host; full encrypted package and manifest after each accepted package change, with dated generations; no network upload. Proposed authenticated encryption: age recipient encryption with an offline owner-controlled private key, separately stored from backup; exact approved tool/version, key generation and custody must be reviewed and separately authorized. Backup and integrity-reference locations are **not selected or approved**. The protected reference is a separately protected owner-controlled offline medium distinct from the evidence directory, containing dated package/version and manifest hashes, acceptance and update history; whether backup and reference media share a device requires explicit owner risk decision. Record media identity without serializing unrelated data. Restore into a separately authorized empty isolated destination, decrypt, recompute each hash and compare against independently protected reference, check completeness and report pass/fail only; never overwrite source. Backup, restore testing, generation, loss/recovery and key compromise procedures require authorization and qualification. Schedule proposed after each accepted package update, with no unattended action until authorized; missed backup is an outstanding failure.

## 3. Identity observation design and unresolved proof

Owner-approved historical weaker-assurance reference: host `mohamed-OptiPlex-3080`, site `v16.localhost`, path `/home/mohamed/frappe-bench/sites/v16.localhost`, database `_6d52b48c328b294e`, socket `/run/mysqld/mysqld.sock`, MariaDB numeric `10.11.14`, full reference `10.11.14-MariaDB-0ubuntu0.24.04.1`, Construction `0.0.5`, ERPNext `16.50.0`, Frappe `16.51.1`. A match is only agreement at observation time, not independent target verification, runtime binding or uninterrupted writer exclusion. Numeric mismatch stops; a changed/unrecognized suffix is UNKNOWN; no implicit normalization or expanded suffix acceptance. Bare version, whitespace or casing variations require an approved rule; do not silently match them. Canonical path comparison must not itself follow unexpected symlinks: verified descriptor walking and separately reviewed mapping are prerequisites.

Principal: propose a purpose-limited local Unix-socket principal with only fixed identity and required visibility rights, no writes, routines or administration. The historical `_6d52b48c328b294e@localhost` is a candidate only, not approved or proved least privileged. No principal is approved by this draft. A separately authorized independent privilege and visibility assessment must establish exact effective identity, grants, server filtering and scope without exposing account lists. Missing proof stops. Connection must not expose credentials in argv, environment, logs or errors; if local socket authentication cannot be implemented with no credential handling, stop. No configuration parser may print, return, log or retain credential fields. A purpose-built reviewed parser must implement the actual Frappe configuration precedence and output only fixed DB/socket match classifications after schema and source checks; effective mapping must be established, and unknown precedence, duplicate keys, unsafe input, path or logging stops. Mapping evidence alone does not prove running code binding. Configuration inspection itself needs a separately scoped grant.

Candidate fixed identity-only queries, subject to prior schema/visibility and read-only verification: `SELECT DATABASE(), @@socket, VERSION()`; fixed reviewed installed-app version query must be derived from verified Frappe version/schema, returning only three approved app version classifications, never arbitrary rows. No query set is accepted or executable until schema and data sources are specified and reviewed. Driver must compare in memory to fixed expected values, verify exactly one row and expected scalar types and bounds, discard raw values; unexpected values emit only generic stop. `DATABASE()` and socket do not by themselves prove site mapping. Avoid routines, arbitrary SQL and database writes. A separate metadata-recollection grant is not implied.

Read-only candidate: one non-reconnecting dedicated connection, autocommit disabled by a reviewed method, `START TRANSACTION READ ONLY`; capture only an internal connection identifier for same-session correlation, never output it. `@@in_transaction` alone does not prove read-only. MariaDB documents `INFORMATION_SCHEMA.INNODB_TRX` with `TRX_MYSQL_THREAD_ID` and `TRX_IS_READ_ONLY`, but visibility, row presence, linkage, session timing, engine coverage and enforcement must be independently qualified for exact version and principal. A candidate verifier might require exactly one own-connection row with `TRX_IS_READ_ONLY=1`, but a missing row, insufficient PROCESS privilege, hidden rows, concurrency ambiguity or unverified engine coverage is UNKNOWN. Do not grant PROCESS automatically or use a broader account. Documentation and a successful SELECT cannot establish complete enforcement. **No non-mutating method is currently qualified**; stop before database identity queries until an independently reviewed and separately authorized lab qualification demonstrates active enforcement and verifier behavior without production writes, including negative controls and visibility failures. DDL, routine calls, reconnect, implicit commits, multi-statements and session changes are forbidden; any disconnect or mode uncertainty stops. Server/client/audit logging needs qualification before any connection.

Before any fixed query, schema and settings compatibility must be assessed using a separately authorized fixed, minimal metadata packet with an approved allowlist: expected object names, column types, nullability, collation, engine and settings expressions; classify each only MATCH/MISMATCH/UNKNOWN in memory, never raw unexpected values. Required visibility is demonstrated by separately reviewed scope-specific privileges and negative controls; zero rows or query success is not proof of visibility or absence. If these checks themselves require a query before read-only verification, the procedure is circular: stop and resolve via separately qualified observation, never assume proof. Unexpected schema, settings, permissions or object count stops. Inventory recollection remains separate.

## 4. Output, cleanup and failure model

Allowed redacted record fields: grant ID/version, procedure version/hash, baseline version, UTC start/end, approved operator role (not personal identity), fixed mechanism ID, stage enum, per-approved-field status MATCH/MISMATCH/UNKNOWN/NOT_RUN, completion COMPLETE/INCOMPLETE, cleanup status CLOSED/UNKNOWN, fixed limitation codes, reviewer/acceptance record references and manifest hashes. No field accepts free text or unbounded input. Use fixed allowlisted enums; generic stop must not identify an unexpected value or indirectly identify a sensitive column: coarsen to stage-level STOP or suppress record entirely when needed. No raw values, error messages, account names, credentials, document IDs or business data. Prevent audit logs and outputs from revealing values through cardinality, filenames or timestamps beyond approved interval. If no safe evidence destination exists, do not run.

On stop: cease queries, attempt `ROLLBACK` on same connection when safe, close connection and local handles, record only bounded enum if safe. Rollback/close failure, disconnect, unknown transaction state, incomplete output, uncertain redaction or inability to confirm cleanup yields INCOMPLETE and requires investigation under a separate scope. Do not claim success, update baseline, retry with broader rights or remove objects of uncertain identity. No routine invocation or writes are permitted. Test design only: qualify path races, ACLs, symlinks, existing objects, interrupted writes/fsync, backup/restore, hidden metadata, wrong schema, malformed outputs, logging leaks, read-only negative controls, connection failure and rollback/close failure in an independently authorized disposable environment. No tests have run.
