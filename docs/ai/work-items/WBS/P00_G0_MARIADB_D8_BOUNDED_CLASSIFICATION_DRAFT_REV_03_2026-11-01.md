## 1. Enumerated candidate classification set (fixed, finite, non-identifying by construction)

These are the only labels a future bounded observation may emit. Each label is a closed symbol carrying no identity semantics, no free text, no numbers from the server, and no substrings of server output.

| Code | Label | Meaning (bounded definition) |
|---|---|---|
| `C1` | `MODE_READONLY` | The observed value equals the single preapproved read-only class value for the correlated dimension |
| `C2` | `MODE_READWRITE` | The observed value equals the single preapproved read-write class value for the correlated dimension |
| `C3` | `MODE_INDETERMINATE` | A value was observed but its identity cannot be established as any preapproved class (unmatched) |
| `C4` | `MODE_ABSENT` | No observation record is visible for the correlated transaction (includes not-started / not-yet-visible, per D5) |
| `C5` | `MODE_WITHHELD` | An observation exists but redaction or binding sufficiency is uncertain; the value is withheld at the boundary |
| `C6` | `MODE_ERROR` | Collection or verification failed and no observation value was obtained (subdivided in §3 by trust-chain outcome) |

The set is closed: any value, condition or outcome not expressible as C1–C6 forces a stop under §3 rule 9, recording **UNKNOWN** with the recorded reason "outside the preapproved enumeration" — never an improvisation, never an extension of the set without a new draft.

## 2. Expected classes (assessment-side, fixed)

| Code | Expected class | Composition rule |
|---|---|---|
| `E1` | `ELIGIBLE_READONLY` | Every required dimension yields `C1`, with correlation, start-proof, freshness and redaction evidence all complete — the **only** class eligible to be *considered* for a match by any future, separately qualified method |
| `E2` | `ADVERSE_READWRITE` | Any required dimension yields `C2` where read-only was expected — an adverse finding, subject to the failure-preservation rule (§3) |
| `E3` | `NO_ESTABLISHMENT` | Any `C4` or `C3` present — no class is established for the assessed transaction |
| `E4` | `UNAVAILABLE` | Any `C5` or `C6` present — the assessment cannot proceed and is withheld or failed as mapped below |

`E1` is eligibility-for-consideration only. This draft declares no match, no pass, and no aggregate result; no aggregate pass may ever be inferred from these classes (disposition conjunct-discipline paragraph: "no aggregate pass is inferred").

**Composition and precedence (explicit):** `E2`, `E3` and `E4` are not mutually exclusive — a multi-dimension outcome may satisfy more than one simultaneously. They are reporting labels with fixed precedence **E2 → E4 → E3 → E1**: an adverse `E2` finding is always surfaced and preserved first and is never masked by any other label; otherwise `E4` reports before `E3`; `E1` applies only when its own composition rule holds (every required dimension `C1`, evidence complete). Precedence governs label reporting only: it never merges, converts or suppresses a status — every §3 rule still assigns exactly one status to its own condition on its own object (fact, attempt/overall assessment, or failure), so non-exclusivity never yields a dual status, and no aggregate pass is inferred.

## 3. Mapping rules (legend-keyed; one status per condition; no silent conversion)

1. `C4` (MODE_ABSENT, including D5's not-started/never-visible records) ⇒ **UNKNOWN** — the fact is not established. Absence is never read as read-only and never as a pass.
2. `C3` (MODE_INDETERMINATE / unmatched value) ⇒ **UNKNOWN** — an indeterminate classification whose value the record cannot establish (disposition D8 rule).
3. `C5` (MODE_WITHHELD / uncertain redaction) ⇒ **INCOMPLETE** — evidence exists but cannot be safely concluded; withhold the value and mark the attempt and overall assessment INCOMPLETE (disposition D8 and Decisions-section rule).
4. `C6` subdivision, by context:
   (a) *Observation-verification context* (this set's domain): a failed integrity check on the observation record itself — digest or signature mismatch ⇒ **FAIL**, never a pass. Safe branch (the failure can be stated without exposing any suppressed value): the attempt and overall assessment record the failure as **FAIL**, visible and preserved, never converted. Leak-risk branch (even a coarse statement of the failure could reveal a suppressed value): withhold it and mark the attempt and overall assessment **INCOMPLETE** (rule 6 treatment). An absent result with no integrity failure ⇒ **UNKNOWN** (the fact of the observation is not established).
   (b) *Public-source provenance context* (retrieved upstream/distribution artifacts): governed exclusively by the disposition's scope-boundary stop conditions. Derivation statement: the two-way disjunction "**UNKNOWN** (fact not established) or **INCOMPLETE** (evidence insufficient or unauthenticated)" resolves to exactly one status per stop by its recorded reason key — UNKNOWN when the reason is that the required fact is not established by the available record; INCOMPLETE when the reason is that evidence exists but is insufficient, unauthenticated, or cannot be safely concluded. Per-trigger enumeration: required trust root missing ⇒ UNKNOWN; trust root present but unverifiable ⇒ INCOMPLETE; signature, digest or descriptor check absent ⇒ UNKNOWN; check fails (conflicting evidence, authentication cannot be concluded) ⇒ INCOMPLETE; artifact does not match the exact recorded version/build, including a changed or unrecognized suffix ⇒ UNKNOWN; source outside the permitted list ⇒ UNKNOWN; material may derive from the reported unauthorized inspection ⇒ UNKNOWN; continued handling risks exposing identities, credentials, suppressed values or other out-of-scope data ⇒ INCOMPLETE (withhold). Each trigger records exactly one status with its reason. Co-occurrence derivation: when several triggers hold on one stop event, each trigger's status and reason remain recorded individually, and the stop event receives exactly one final status — **UNKNOWN** if any co-occurring trigger's reason is that a required fact is not established (the event includes an unestablished fact), otherwise **INCOMPLETE** (every fact bearing on the event is established but its evidence is insufficient, unauthenticated or cannot be safely concluded); precedence selects among legend-consistent recorded reasons, never converts one status into the other, and never yields a pass. This enumeration instantiates, and does not alter, the disposition's stop conditions. The two contexts are distinct — (a) concerns a future observation record, (b) concerns artifact provenance — and neither context's mapping may be applied to the other.
5. Correlation integrity lost (same-transaction identity cannot be established) ⇒ **UNKNOWN**; freshness or timing evidence present but insufficient to conclude ⇒ **INCOMPLETE** (disposition conjunct discipline: missing fact ⇒ UNKNOWN, underdetermined evidence ⇒ INCOMPLETE).
6. `C2` (adverse) ⇒ preserved as an adverse finding. Safe branch (no suppressed value at risk): the attempt and overall assessment record the adverse finding as **FAIL**, visible and preserved, never converted to pass. Leak-risk branch (even a coarse statement could reveal a suppressed value): withhold it and mark the attempt and overall assessment **INCOMPLETE**; a missing record or incomplete state never erases a known failure (D13).
7. UNKNOWN and INCOMPLETE are distinct and non-interchangeable; neither converts to the other or to a pass (legend).
8. Version-context precondition for every rule in this section: classification is meaningful only under the exact recorded references (numeric core `10.11.14`, full reference `10.11.14-MariaDB-0ubuntu0.24.04.1`); a changed or unrecognized suffix renders the observation **UNKNOWN** (not evaluable), and no substitution, interpolation or family inference is permitted.
9. **Out-of-enumeration condition** (any value, condition or outcome not expressible as C1–C6, per §1): ⇒ **UNKNOWN** — the record cannot establish its class within the preapproved enumeration; record the reason "outside the preapproved enumeration" and stop. Exactly one status; never continued past, never improvised, never extended without a new draft.
10. **Unqualified comparison** (any comparison not supported by a separately qualified method under D8) ⇒ **UNKNOWN**, reason "unqualified comparison". By construction this draft performs no comparison, so this condition is unreachable here; it is routed explicitly for completeness and is not left unmapped. Any future comparison lacking the qualified method records UNKNOWN and stops.

**C1 status note (intentional):** `C1` (`MODE_READONLY`) intentionally carries no §3 status rule of its own. `C1` is an observation label that routes only to the expected classes in §2 (`E1` eligibility); this draft declares no match and no pass, so no determination status attaches to `C1`. This absence is intentional and is not a mapping gap: `C1` is not a failure or stop condition, and eligibility is never itself a status.

**Cross-rule precedence note (shared attempt-and-overall-assessment object):** where several §3 rules could touch the same attempt and overall assessment, the current combinations agree: every leak-risk path assigns INCOMPLETE (rules 3, 4(a), 6); every safe path assigns FAIL visibly (rules 4(a), 6); the remaining rules (1, 2, 5, 8, 9, 10) state statuses on their own recorded facts. Rule 10's UNKNOWN is recorded on the attempted comparison's classification fact (reason "unqualified comparison"), never as an overall-assessment status; rule 3 assigns the attempt/overall INCOMPLETE whenever it is active, and that assignment does not exclude a **FAIL** on the failure object recorded under the rules 4(a)/6 branches — FAIL remains visible on its own object when safe and is never converted — while rule 3 continues to govern the attempt/overall object whenever it is active. The only latent tension — that UNKNOWN fact coexisting with rule 3's INCOMPLETE on the overall assessment under a hypothetical unqualified comparison with uncertain redaction — is unreachable in this draft, which performs no comparison; should it ever become reachable under a future separate authorization, that future draft must resolve it explicitly before use; nothing here pre-decides it. **"At risk" predicate (suppression):** a statement is at risk precisely when any value it would convey has uncertain redaction sufficiency (rule 3 active) or could permit inference of a suppressed value; the predicate is assessed per statement — so whenever rule 3 is active the safe branches' precondition ("no suppressed value at risk") is false, the leak-risk branch governs, and the combinations above agree. The §2 precedence clause continues to govern `E`-label reporting only.
