# Agent Workflow - Construction ERP

This file defines the shared operating contract for all agents working on the Construction ERP app.

## 1. Universal Rules

These rules apply to Architect, Reviewer, Builder, and Final Reviewer.

1. Start from repo root: `/home/mohamed/frappe-bench/apps/construction`.
2. Read `AGENTS.md`, `SESSION_MEMORY.md`, `docs/ai/CONTEXT_INDEX.md`, and this file before planning or editing.
3. Run the pre-agent verification gate before implementation work:

```bash
python3 scripts/schema_drift_checker.py
python3 scripts/ai_context_check.py
git status --short
```

4. Treat live code and DocType JSON as authority. MCP memory and old docs are cache/context only.
5. Never reference `modules/`, `.ai/`, `SESSION_LOG.md`, or `DEBUG_TRACE.md` as mandatory paths for this repo.
6. Use `docs/ai/active/` for active baton files and `docs/ai/archive/` for completed handoffs.
7. Every baton file must include: repo path, branch, commit hash, files read, files changed, commands run, result, and known gaps.
8. Preserve user changes. Do not revert unrelated dirty working-tree files.
9. Use parameterized SQL only. Never build SQL with f-strings or string concatenation.
10. Verify schema-sensitive work against `construction/construction/doctype/*/*.json`.

## 2. Required Skills by Role

| Role | Required Skills | Output |
|---|---|---|
| Architect | Frappe/ERPNext architecture, DocType schema reading, BOQ/scope/theme/VFC awareness, risk analysis | `docs/ai/active/PLAN.md` |
| Reviewer | adversarial review, security/performance review, permission and data-integrity analysis | `docs/ai/active/REVIEW.md` |
| Builder | scoped implementation, Frappe hooks/controllers/API/client scripts, focused tests, migration discipline | `docs/ai/active/IMPLEMENTATION.md` |
| Final Reviewer | code review, diff validation, test evidence review, release-gate judgment | `docs/ai/active/FINAL_DIFF.md` |

## 3. Architect Contract

The Architect converts a human request into a buildable plan.

Must read:

- `AGENTS.md`
- `SESSION_MEMORY.md`
- `docs/ai/SCHEMA_FACTS.md`
- relevant DocType JSON files
- relevant Python/JS/CSS files

Must write:

- `docs/ai/active/PLAN.md`

Must not:

- invent fields that are not in live DocType JSON,
- skip permission, scope, or migration impact,
- approve its own plan for implementation.

## 4. Reviewer Contract

The Reviewer attacks the plan before code is written.

Must read:

- `docs/ai/active/PLAN.md`
- `docs/ai/SCHEMA_FACTS.md`
- referenced live files

Must write:

- `docs/ai/active/REVIEW.md`

Review focus:

- schema drift,
- permissions and role checks,
- SQL safety,
- Frappe hook side effects,
- scope context leakage,
- migrations and patch order,
- N+1 queries and broad query hooks,
- missing tests.

## 5. Builder Contract

The Builder implements only the approved plan plus approved review corrections.

Must read:

- `docs/ai/active/PLAN.md`
- `docs/ai/active/REVIEW.md`
- referenced live code

Must write:

- `docs/ai/active/IMPLEMENTATION.md`

Must run:

- the smallest meaningful test command for touched code,
- `python3 scripts/schema_drift_checker.py` if DocType JSON changed,
- `python3 scripts/ai_context_check.py` before handoff.

Must log deviations from the plan immediately in `IMPLEMENTATION.md`.

## 6. Final Reviewer Contract

The Final Reviewer decides whether the work is ready for human approval.

Must read:

- `docs/ai/active/PLAN.md`
- `docs/ai/active/REVIEW.md`
- `docs/ai/active/IMPLEMENTATION.md`
- `git diff`
- all touched files with behavior changes

Must write:

- `docs/ai/active/FINAL_DIFF.md`

Verdict must be exactly one of:

- `PASS`
- `PASS_WITH_NOTES`
- `FAIL_FIX_REQUIRED`

Fail if:

- implementation does not match the approved plan,
- tests were skipped without a defensible reason,
- schema facts drift,
- permissions or scope filtering are likely broken,
- unrelated user changes were reverted or overwritten.

## 7. Memory Enhancement Rules

1. `docs/ai/SCHEMA_FACTS.md` is generated by `scripts/schema_drift_checker.py --update`.
2. `SESSION_MEMORY.md` remains the tactical memory file.
3. `scripts/ai_memory_pruner.py --dry-run` is safe to run anytime.
4. `scripts/ai_memory_pruner.py --auto` must create a timestamped backup before writing.
5. MCP MemoryGraph is derived cache. If it conflicts with repo files, repo files win.
6. Post-commit MCP capture may store commit summaries, but it must not become a release gate.

## 8. Standard Handoff Commands

Pre-agent:

```bash
python3 scripts/schema_drift_checker.py
python3 scripts/ai_context_check.py
git status --short
```

Before final handoff:

```bash
python3 scripts/schema_drift_checker.py
python3 scripts/ai_context_check.py
git diff --stat
```

Memory maintenance:

```bash
python3 scripts/ai_memory_pruner.py --dry-run
```
