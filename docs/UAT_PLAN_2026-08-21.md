# Client UAT Plan — Three-Role Acceptance Testing

**Date:** 2026-08-21
**Prepared per:** Consultant handoff `CONSULTANT_HANDOFF_GM_2026-08-21.md`, Risk R3
**Applies to:** Construction ERP release `88493fc` (develop), User Guide v1.3

---

## Why three logins, not one

The system enforces role-based permissions. A single-user smoke test only proves that one person's doors work. Permission failures — a Site Engineer who can secretly edit prices, or a Project Manager who cannot read the reports he needs — are **invisible unless you log in as each role**. This plan closes that gap with ~30 minutes of extra testing.

## Test accounts to create (before starting)

| Account | Role assigned | Purpose |
|---|---|---|
| `uat.owner@<client-domain>` | **Construction Owner** | Full-access verification |
| `uat.pm@<client-domain>` | **Project Manager** | Read-cost / no-edit verification |
| `uat.engineer@<client-domain>` | **Site Engineer** | Restriction verification |

Assign roles from **User → Roles**, then verify each user can log in before running the checklists. Do all tests in one shared scope: enable Scope Context and select the same Company + Project in the top bar for every session.

## Pass criteria & sign-off

- Every row above matches its "Expected" column.
- **Any permission leak (a role seeing/changing more than allowed) is a launch blocker** — record it, stop UAT, notify the development team.
- Any workflow blockage (a role unable to do its legitimate job) is also a blocker.
- Record results per row (Pass/Fail/N-A + screenshot), attach to the UAT report.

## After UAT passes

GM issues final client acceptance; team executes the production deployment sequence from Runbook §0.2 (`scripts/preflight_check.sh` → backup → migrate → build → restart → non-admin smoke test).
